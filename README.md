# Creator Attribution Engine

> An end-to-end ML pipeline that determines which travel creators actually drive booking demand — built with Markov chain attribution, Shapley values, XGBoost, and BERT sentiment analysis on real YouTube data.

## The Problem

Travel platforms pay creators based on **last-click attribution** — whoever a user saw last gets 100% of the credit. A user might watch three creators over two weeks before booking. Last-click ignores the first two completely.

This project builds a fairer system using real YouTube data, Google Trends, and mathematical models from cooperative game theory.

## How It Works

```
YouTube API          Google Trends        BERT (HuggingFace)
     ↓                    ↓                      ↓
250 videos           Demand spikes          Comment intent
1,352 comments       per destination        per creator
     ↓                    ↓                      ↓
              Feature Engineering (23 features)
                           ↓
              XGBoost Quality Score + SHAP
                           ↓
         Markov Chain Attribution + Shapley Values
                           ↓
                  Streamlit Dashboard
```

## Pipeline

| Step | File | What it does | Time |
|---|---|---|---|
| 1 | `step1_scrape_youtube.py` | Scrapes videos + comments via YouTube Data API | ~5 mins |
| 2 | `step2_scrape_trends.py` | Pulls Google Trends, detects spikes, builds label | ~3 mins |
| 3 | `step3_sentiment.py` | Runs BERT sentiment on all comments | ~15 mins |
| 4 | `step4_build_features.py` | Engineers 23 features, joins all data | ~1 min |
| 5 | `step5_train_model.py` | Trains XGBoost + Markov + Shapley models | ~2 mins |

## Tech Stack

**Data**
- YouTube Data API v3
- pytrends (Google Trends)

**NLP**
- `cardiffnlp/twitter-roberta-base-sentiment-latest` — RoBERTa trained on 58M tweets
- Custom regex — 22 booking intent patterns

**ML**
- XGBoost — gradient boosted trees for creator quality scoring
- SHAP — model explainability
- Platt scaling — probability calibration
- 5-fold stratified cross-validation

**Attribution**
- Markov chain removal effects
- Shapley values (cooperative game theory)
- Last-click baseline for comparison

**Dashboard**
- Streamlit + Plotly
- 6 pages including a live Payout Calculator

## The Label

Real booking data is not publicly available. This project uses **Google Trends spike detection** as a proxy.

If a video mentions Lisbon and Google searches for "flights to Lisbon" spiked in the dataset — `drove_intent = 1`.

A spike = any week where search volume exceeds 1.5× the rolling 4-week average. The rolling window handles seasonality automatically.

In production: swap the Google Trends label for a `booking_confirmed` event. The entire architecture stays the same.

## Limitations

**ROC-AUC of 1.0** — The label is derived from `max_spike_mag` which is also a feature, creating a circular relationship. In production with real booking data this disappears.

**Dataset size** — 250 videos, 5 channels. Production would need thousands of creators.
